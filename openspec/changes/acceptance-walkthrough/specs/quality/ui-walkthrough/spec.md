# Spec Delta

## Purpose

逐页检查界面交互是否现代、一致、友好、省操作，把 UI 体验问题在交付前系统地找出来，而不是靠零散反馈。

## ADDED Requirements

### Requirement: 页面清单与走查矩阵
UI 走查 SHALL 基于完整页面清单（管理台、协同中心、各工作台、设计器、移动端），每个页面在手机、平板、桌面三种视口和浅色、深色两种主题下检查；页面清单 SHALL 与路由表自动比对，新增路由未纳入清单时走查报告给出提示。

#### Scenario: 遗漏页面
- **WHEN** 新增路由 `/quality/audit` 未写入页面清单
- **THEN** 走查报告列出该路由为"未走查页面"

### Requirement: 可用性启发式检查
每个页面 SHALL 按统一检查清单逐项评估：状态可见、与用户习惯一致、可撤销与可退出、一致性、防错、少记忆多识别、效率与快捷方式、简洁、错误可理解可恢复、帮助可得；每项给出通过、问题或不适用及说明。

#### Scenario: 记录问题
- **WHEN** 走查员发现某页面删除操作没有说明后果
- **THEN** 在"防错"项记为问题，附截图并生成缺陷

### Requirement: 设计系统一致性
UI 走查 SHALL 检查页面只使用设计令牌与统一组件：按钮层级、间距、字号、状态标签、空态、加载、错误态、确认框和提示文案风格一致。

#### Scenario: 不一致的空态
- **WHEN** 某列表无数据时显示空白表格而非统一空态组件
- **THEN** 记为一致性问题

### Requirement: 关键交互专项检查
UI 走查 SHALL 专项验证 `modernize-ui-ux` 中的关键交互：命令面板、保存视图、抽屉详情与连续办理、草稿自动保存与恢复、Excel 粘贴、扫码、批量操作与部分失败、撤销、可操作错误提示、新手引导、离线报工。

#### Scenario: 草稿恢复专项
- **WHEN** 走查员填写到一半强制刷新页面
- **THEN** 重新打开后出现恢复草稿提示且内容完整

### Requirement: 操作成本实测
UI 走查 SHALL 实测关键任务的点击数和完成耗时（报工、审核、报缺陷、配置一张台账），与预算对比并记录。

#### Scenario: 超出预算
- **WHEN** 实测移动报工需要 7 次点击
- **THEN** 记为 S2 体验缺陷并标注超出预算的步骤

### Requirement: 无障碍与键盘走查
UI 走查 SHALL 在自动化扫描之外，对核心页面做纯键盘操作和屏幕阅读器抽查，确认焦点顺序合理、焦点可见、弹层可用 Esc 关闭。

#### Scenario: 焦点丢失
- **WHEN** 关闭抽屉后焦点没有回到触发按钮
- **THEN** 记为无障碍问题
