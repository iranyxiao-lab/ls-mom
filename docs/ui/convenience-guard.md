# 便利功能不绕过服务端

默认值、记住上次填写、自动带入、从 Excel 粘贴、扫码、批量编辑只是帮用户更快地填出取值，**提交时与手工输入完全一样**经过服务端校验：台账层（字段类型、必填、引用可见性与数据范围、字段权限）→ 表单层（冻结版本的 FormSchema 校验、引用过滤、规则）→ Operation 守卫。前端的预检只为了早点提示，不能代替服务端。

## 引用被拒时说明原因

| 编码 | 情况 | 字段下的提示 | 检查位置 |
| --- | --- | --- | --- |
| `INVALID` | 引用对象已删除或不存在 | 所选设备已删除或不存在，请重新选择 | 台账层 |
| `INVALID` | 对象不在调用者的数据范围内（如班长引用车间设备） | 你无权使用所选设备，请重新选择 | 台账层 |
| `REF_INACTIVE` | 对象状态不满足表单的状态过滤（如设备已报废） | 该设备已报废，请重新选择 | 表单层 |
| `REF` | 不满足表单的其他过滤（如只能选本组织的） | 相关设备不在允许的引用范围内 | 表单层 |

- 状态说明取状态机里进入该状态的迁移名称（`SCRAPPED` ← 「报废」→「已报废」）；初始状态（如未投用的 `DRAFT`）为「尚未启用」；没有状态机时显示状态编码。
- 修改已有记录时，**未改动的引用不复核**：记录里的设备后来报废或移出范围，不妨碍修改其他字段；改成别的对象时照常检查。
- 按编号回显已有取值（`/api/form/ref/search` 带 `ids`）不套表单过滤、只按数据范围，所以带出的已报废设备仍显示名称，用户能看出是哪一台、为什么要换。

## 三种典型情况

| 情况 | 前端 | 服务端 |
| --- | --- | --- |
| 记住的设备已报废 | 照常带出并标"上次填写" | 保存时拒绝，设备字段提示"该设备已报废，请重新选择"；改选后保存成功并更新记忆值 |
| 粘贴超长的名称（表单没声明长度，只有 Concept 有） | 放行 | 拒绝并标在该单元格："第 2 行：工器具最多 100 个字符" |
| 扫到数据范围外的设备 | 扫码接口按同一套过滤与数据范围查找，字段下提示"没有找到编码为「X」的设备，或你无权使用" | 绕过界面直接提交该设备编号同样被拒："你无权使用所选设备，请重新选择" |

失焦校验不会用"必填"之类的通用提示覆盖服务端或扫码给出的具体原因；字段取值改动后原因才清除。

## 示例配置

标准质量 Pack（ls.quality 1.0.2，不符合项表单 v2）的「相关设备」只可选在用状态（运行、备用、停机检修、停机），并记住上次选的设备：

```json
{ "key": "asset", "widget": "assetRef", "remember": true,
  "ref": { "concept": "ls.asset.Asset", "labelField": "name",
           "filter": [{ "field": "status", "op": "in", "value": ["RUNNING", "STANDBY", "MAINTENANCE", "STOPPED"] }] } }
```

通用台账的新增表单会使用自动带入和记忆值，保存成功后才更新记忆值。
