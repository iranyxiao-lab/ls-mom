# 草稿自动保存与会话过期

## 草稿

调用 `SchemaForm` 时传入 `draft-key`，表单就会自动保存草稿。草稿键由表单或 Concept 编码加记录 id 组成，新单据用 `new`，例如 `ls.asset.Defect:new:asset-12`。

- 用户改动表单后，停止输入 3 秒即保存。只有预填值、用户没有动过时不保存。内容摘要（键顺序无关）与上次相同时不重复写。
- 草稿同时写入两处：本机 IndexedDB（`ls-form-drafts`，按用户隔离）和服务端 `ui_form_draft`（`PUT /api/ui/drafts/{key}`）。断网或会话过期时只写本机，下次内容变化时再写服务端。离开页面（页面隐藏或关闭）时会立即保存一次。
- 再次打开同一表单时，取本机与服务端中较新的一份。如果它和当前内容不同，就提示「发现未提交的草稿（时间）」，用户可以选择恢复或丢弃。恢复已有记录的草稿时，保留当前记录的 id 和版本号，版本冲突仍由服务端判断。
- 提交成功后调用方执行 `clearDraft()`，同时删除本机和服务端的草稿。退出登录时清掉本机草稿；服务端草稿保留，重新登录后仍可恢复。
- 服务端每人最多保留 200 份草稿，单份不超过 512 KB。草稿不是业务数据，提交时照常经服务端校验。

目前接入草稿的有：通用台账录入（`LedgerWorkspace`）和设备台账的「登记缺陷」。

## 会话过期

请求收到 401 时，布局里的登录框（`ReloginDialog`）会原地弹出，账号已经填好，只需输入密码（启用验证码时还要输入验证码）。登录成功后，原请求按原样重发：保留加密前的请求体，并沿用原来的幂等键，所以服务端只会保存一次。页面和填写的内容都不会变。同时过期的多个请求共用这一次登录。取消登录时，请求按失败处理，填写的内容仍保留在草稿里。登录页等没有布局的页面，仍按原来的方式提示重新登录。

后台请求（如草稿保存）带 `silentAuth` 头，401 时不弹登录框。

端到端测试见 `tests/ui/app/drafts.spec.ts`：关闭浏览器后恢复草稿，以及会话过期后原地登录、继续提交。
