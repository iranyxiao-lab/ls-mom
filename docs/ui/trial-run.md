# 设计器沙箱试运行

表单设计器的「试运行」页签：用**当前草稿**填写一张单据，以各节点候选办理人的身份走完绑定的审批流（提交 → 审核 → 确认），
不写入正式数据，结束后可一键清除试运行轨迹。

## 用法

1. 打开表单设计器 → 「试运行」。页面显示绑定的已发布审批流与节点；表单未绑定已发布流程时不能试运行。
2. 选择发起人（列出拥有提交权限的人，默认第一个）。
3. 按草稿填写单据；为每个人工节点选择「通过 / 驳回」，并填写该节点字段策略中可编辑的字段（带 * 的为必填）。
4. 「开始试运行」：显示结果与轨迹——每一步的办理人（标"模拟·姓名（角色）"）、决定、单据状态、节点可编辑字段、回调执行情况；
   失败的步骤标红并给出原因（如"节点要求填写该字段"、"没有可办理的人"）。
5. 「清除试运行数据」删除本人在该表单上的全部试运行轨迹。

## 实现

- 接口：`GET /api/flow/trial/setup?formCode=`、`POST /api/flow/trial`、`GET /api/flow/trial?formCode=`、`DELETE /api/flow/trial?formCode=`，
  权限 `lsmom:form:design`。
- `TrialRunner` 在 `Sandbox` 标记下开启只回滚事务：流程启动、回调、拒绝审计等原本的独立事务并入当前事务，提交后回调立即执行；
  事务结束时业务表、`biz_flow_instance`、`biz_task`、`biz_flow_callback_log`、`core_domain_event`、`op_audit` 与临时草稿版本全部回滚。
- 草稿在沙箱内存为临时版本，试运行实例改绑到该版本，节点字段策略按草稿校验。
- 办理身份：`ActorResolver.simulate(party)` 按该人账号当前的角色、菜单权限与数据范围构造，与真人登录后的权限一致；
  默认取待办的第一个候选人，因此办理人规则（角色 + 业务组织）配错会在试运行中直接暴露。
- 只有轨迹写入 `flow_trial_run`（V210），一键清除即删除。

## 验证

`node plus-ui/tests/e2e/trial-run.e2e.mjs`：生成借还台账 → 试运行（未填审核意见时失败并指出节点 → 填写后通过）→
核对业务表、流程实例、待办、事件、审计、表单版本数量不变 → 一键清除后试运行数据为 0。
